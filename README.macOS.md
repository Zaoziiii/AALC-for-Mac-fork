# AALC Mac mac.14 使用指南

适用于 Apple Silicon Mac、macOS 14 或更新版本、CrossOver/ CrossOver Preview 中的 Steam《边狱公司》。这是独立的 Mac 移植分支，不提供 Windows 兼容运行路径；Intel Mac 尚未验证。

## 安装和首次启动

1. 获取 mac.14 应用包并解压，把 `AALC Mac.app` 放到“应用程序”。预构建应用无需安装 Python；没有应用包时可按下方步骤构建。
2. 应用使用本地临时签名，未经过 Apple Developer ID 公证。如果 macOS 阻止打开，可在“系统设置 → 隐私与安全性”查看对应的打开提示。
3. 在“系统设置 → 隐私与安全性”中，给当前这份 **AALC Mac** 开启“屏幕录制”（部分系统称“屏幕与系统音频录制”）和“辅助功能”，然后完全退出并重开。更换构建后若授权不生效，移除旧条目并添加实际运行的应用。
4. 用 CrossOver 正常启动 Steam 中的游戏。**不使用旧实验版测试启动器，不需要修改 CrossOver 或加载动态库。** Steam 应保持已登录。
5. 游戏使用普通 16:9 窗口，建议客户区 1920×1080；英文界面有实机验证记录。简体中文本地化依赖对应素材，不能据此保证所有界面均已验证。
6. 打开右上角“权限与游戏检测”，检查当前应用路径、权限和游戏截图。需要调整尺寸时先停止任务，再使用“将游戏窗口调整为 1920×1080”。预览应无标题栏、无裁切偏移。
7. 配置队伍和任务，确认体力、模块及狂气相关选项，再点击 `Link Start!`。

## 前台与后台模式

在“设置 → 游戏设置 → 操控方式”选择模式，下次开始任务时生效。

| 模式 | 操作与限制 |
| --- | --- |
| CrossOver 后台 | 点击、按键及一般拖动发送到游戏进程，可使用其他应用，允许普通遮挡。仅地图拖动短暂借用真实鼠标。 |
| macOS 前台 | 占用鼠标键盘，游戏须保持前台且可见；切换应用或遮挡会停止输入。 |

后台游戏须保留在当前桌面，不能最小化、隐藏、锁屏，任务中不要移动或缩放窗口。后台滚轮不支持，地图保持默认缩放，列表使用拖动。

### 地图拖动与路线规划

游戏读取系统真实光标坐标，因此地图不能只靠后台拖动事件控制。mac.14 在地图对齐时先等待键鼠空闲 **1.5 秒**，暂时解除物理鼠标与光标联动，沿指定路径移动光标并发送游戏拖动事件；释放后把光标放回原处并恢复联动。发生取消或异常也执行清理。典型拖动约 1–2 秒，实际占用取决于调整次数。

地图调整后恢复原版节点、连线识别和路线缓存。权重：问号事件 1、商店 2、普通战斗 4、集中/Boss 6、高风险 7；选择总权重最小的路线，并非每一步无条件选问号。未识别到 Boss 时规划范围受可见列限制。完整路线识别失败时，可通过已确认的巴士箭头选择下一步，之后重新规划；缓存路线也会检查当前可走方向。

### 暂停和接管

- `Ctrl+Q`：停止任务。
- `Option+P`：暂停，手动接管游戏。
- `Option+R`：恢复。

辅助功能权限是全局快捷键的前提。后台模式有前台保护：检测到游戏抢到前台时尝试切回原应用；暂停期间不切走游戏。启动/重启游戏仍可能短暂显示在前台。

## 镜牢意外退出后自动重启

该功能在镜牢任务的窗口丢失恢复路径中自动生效，无需额外开关：

1. 确认 `LimbusCompany.exe` 已退出。若进程仍存在，例如最小化、隐藏或在其他桌面，停止并提示，不重启。
2. 把存在的 `Player.log` 和 `LimbusCompany_d3d11.log` 保存到 AALC 日志下的 `crash-日期-时间/`，避免下一次启动覆盖。
3. 找到安装游戏的 CrossOver 容器，优先使用正在运行的 CrossOver 版本，通过容器内 Steam 启动游戏（应用 ID `1973530`）。
4. 最多等 **300 秒**出现窗口，再最多等 **180 秒**识别标题/主界面；此阶段只截图等待。标题等待超时后会尝试返回主界面，不能保证恢复成功。
5. 主任务接管新窗口，返回主界面并尝试继续同一次镜牢；恢复期间暂停服务器重试监控，避免旧窗口状态中断恢复。
6. **30 分钟内超过 3 次退出**时停止自动重启。窗口超时、容器不存在等错误也会停止并记录。

仅“游戏进程退出”可触发，不是通用卡死检测，不会强制结束仍在运行的游戏。挂机期间手动退出游戏也可能被视为意外退出；需要退出时先停止 AALC。日常任务不承诺同样的自动恢复。

容器发现目前使用 CrossOver 的默认 Bottles 目录和标准 Steam 游戏路径；自定义 Steam 库路径、多份游戏安装、其他 Wine 发行版未验证。它不能修复 CrossOver 图形层自身的崩溃原因。

## 配置、日志和问题反馈

数据保存在 `~/Library/Application Support/AALC Mac/`，应用内“设置 → 日志”可打开日志目录。升级沿用此目录；不要导入 Windows 版 `config.yaml`。

反馈时提供 mac.14 版本号、macOS/CrossOver 版本、输入模式、报错时间和相关日志；识别问题附当时游戏画面。不要公开账号信息或整份私人配置。

- **授权了仍提示未授权**：确认设置里授权的路径与实际运行应用一致，重新添加后完全退出重开。
- **找不到窗口**：先确认游戏仍运行且位于当前桌面，没有隐藏或最小化；普通遮挡与隐藏不是一回事。
- **暂时不拖地图**：检查是否持续操作键鼠；拖动会等待空闲。需要接管时暂停任务。
- **无法识别巴士/楼层**：保持默认缩放和完整游戏内容，保存截图与日志，不要不停重试盲拖。
- **反复崩溃**：查看 `crash-*` 里的游戏日志，先排查 CrossOver 图形设置；自动重启不能替代崩溃诊断。

## 从源码运行、测试和构建

需要 Apple Silicon macOS、Python 3.12 和 Xcode Command Line Tools。使用本分支源码：

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-macos-lock.txt
.venv/bin/python main.py
```

源码运行时需为实际使用的终端/Python 进程授权。测试与构建：

```sh
.venv/bin/python -m pytest -q
./build_macos.sh
```

构建脚本在系统临时目录生成应用、执行临时签名及严格签名检查，输出 `dist/AALC-Mac-arm64.zip`。可通过 `PYTHON_BIN` 指定现有 Python 环境。首次安装依赖、模型准备和构建可能需要网络。
